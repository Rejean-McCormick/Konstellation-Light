# Konstellation Light — bêta ML6, source publique Wikidata

Six langues : fr, en, es, it, fi, de. Le workflow distinct `konstellation-light-127-ml6-wikidata.yml` accepte une confirmation `PUBLIER_127_ML6_WIKIDATA` et une empreinte `sha256:...` du fichier `public-ml6-source/scope.json`.

Le périmètre est produit localement par rapprochement des enregistrements diK V5.21.6.1 validés avec les identités projetées et les correspondances exactes déjà acceptées dans la surface publique. Le fichier de périmètre contient seulement des identifiants et empreintes de fichiers publics, aucun texte lexical privé, aucune DB ni décision inventée. Le workflow refuse un index différent. Il récupère par lots uniquement les six langues des identifiants Wikidata publics sélectionnés, sans fallback ni redirection, sans claims. Les libellés, alias et descriptions sont des données source CC0, non révisées éditorialement. La provenance comprend l'identifiant Wikidata, la révision de source, l'empreinte de la réponse, les empreintes du graphe et du crosswalk. La description source n'est pas une définition canonique. Aucun enrichissement d'identité ou assertion n'est créé.

Les six langues peuvent être interrogées sur chaque identité sélectionnée même si l'ancien lot diK n'en contenait qu'une partie. Les résultats Wikidata sont rechargés à chaque construction; la couverture et les révisions lexicales peuvent varier. Le périmètre d'identités, l'index et les graphes restent épinglés. Les tests de recette sont des échantillons, pas une certification exhaustive.

Le contrat historique des traductions révisées demeure le chemin par défaut. Le statut `public_source` est uniquement admissible via l'option explicite de la bêta source; les candidats sont toujours refusés par les validations de publication. Le contrôle C4 ordinaire refuse cette nouvelle surface. La vérification dédiée garantit seulement l'intégrité et le raccordement au périmètre; aucun reçu C1–C4 n'est créé. Le workflow de bêta distinct nécessite la confirmation du propriétaire et les tests de navigateur réussis avant le déploiement. Aucun lancement automatique, aucune lecture de la base privée dans GitHub Actions. Les autres workflows restent inchangés.
